# Dependency groups (documentation only)

This page documents how ARTEMIS dependencies are grouped for lightweight installs
(e.g. Termux). **It does not change any install**: `pyproject.toml` and `uv.lock` are
unchanged, and the default desktop install (`uv sync` / `pip install artemis`) still
installs everything. Turning groups into pip extras is a separate, not-yet-approved step.

| group | packages (examples) | loaded by `artemis --help`? |
|---|---|---|
| Core (minimal runtime) | typer, rich, pydantic, pydantic-settings, python-dotenv, jinja2, httpx, requests, langgraph, langchain-core, psutil, artemis-client, google-genai, langchain-google-genai | yes |
| Android/ADB control | adbutils, uiautomator2 (+lxml), pillow | yes |
| Required transitive | orjson, ormsgpack, zstandard, uuid-utils, PyYAML, pydantic-core, websockets, typing-extensions, aiohttp (via google-genai) | yes, via core |
| Optional providers | langchain-openai, langchain-anthropic, langchain-google-vertexai | no, imported when the provider is selected; missing package -> `ProviderUnavailableError` |
| Vision / media / code execution | opencv-python (cv2), numpy, imageio-ffmpeg, jupyter-client, pyzmq, ipykernel | no, lazy; missing package -> `OptionalDependencyError` |
| MCP / web server | mcp server stack (uvicorn, starlette, sse-starlette), fastapi | no, imported when a server starts (`artemis mcp`, `artemis ui`) |
| No static consumer found | scipy, matplotlib, langchain, langchain-community, langchain-mcp-adapters, inquirer, sseclient-py, posthog, retry | no (code generated by the image processor may still import scipy/matplotlib in its Jupyter kernel) |

The regression tests `tests/unit/test_lightweight_imports.py`,
`tests/unit/test_cli_import_boundaries.py` and `tests/unit/test_provider_unavailable.py`
encode the "loaded by `artemis --help`?" column.
